# TON Vault — кастомный контракт-хранилище

Контракт **не является** обычным TON-кошельком (Wallet V4/V5) и не привязан
к сид-фразе. Это отдельный смарт-контракт со своей логикой:

- хранит TON, принимает депозиты от кого угодно;
- выводит TON и NFT **только** по команде адреса `owner`, заданного при деплое;
- владельцем может быть любой ваш адрес — хоть обычный кошелёк, хоть
  другой смарт-контракт, хоть мультисиг;
- сид-фразы у самого Vault нет и не нужно — авторизация идёт по адресу
  отправителя внутреннего сообщения (`sender() == self.owner`).

## Структура

```
ton-vault/
├── contracts/
│   └── vault.tact        # сам контракт
├── scripts/
│   └── withdraw.js        # пример вывода TON владельцем
├── package.json
└── README.md
```

## 1. Установка окружения

```bash
npm install
```

Понадобится [Blueprint](https://github.com/ton-org/blueprint) — стандартный
фреймворк для разработки на TON (компиляция Tact, деплой, тесты).

## 2. Компиляция

```bash
npx blueprint build
```

После сборки в `build/Vault/` появится:
- `Vault.abi` — там будут реальные **opcodes** сообщений (`Withdraw`,
  `SendNft`, `ChangeOwner`) — их нужно подставить в скрипты вместо
  `0x_OPCODE_...`;
- `Vault.code.boc` — скомпилированный код контракта.

## 3. Деплой

```bash
npx blueprint run deploy
```

Blueprint предложит выбрать сеть (testnet/mainnet) и способ подписи —
через TonConnect (кошелёк в телефоне) или через мнемонику деплоера.
При деплое передаётся `init(owner: Address)` — адрес, который станет
владельцем Vault.

⚠️ **Рекомендация:** сначала разверните и протестируйте на **testnet**
(https://t.me/testgiver_ton_bot — получить тестовые TON).

## 4. Депозит

Просто отправьте TON на адрес Vault — любой транзакцией, хоть из
Tonkeeper. Контракт примет любую входящую сумму.

## 5. Вывод TON

Отредактируйте `scripts/withdraw.js`:
- `VAULT_ADDRESS` — адрес развёрнутого Vault;
- `WITHDRAW_TO`, `WITHDRAW_AMOUNT_TON`;
- `OWNER_MNEMONIC` — сид-фраза **вашего кошелька-владельца** (не Vault!),
  тот, чей адрес был указан как `owner` при деплое;
- opcode `Withdraw` — взять из `build/Vault/Vault.abi`.

```bash
OWNER_MNEMONIC="слово1 слово2 ... слово24" node scripts/withdraw.js
```

## 6. Отправка NFT

Чтобы Vault мог отправить NFT — он должен быть текущим **owner'ом**
этого NFT-айтема (т.е. NFT должен быть переведён на адрес Vault заранее,
обычным transfer-сообщением стандарта TEP-62).

Дальше отправляете внутреннее сообщение `SendNft { nftAddress, newOwner,
forwardAmount }` тем же способом, что и `Withdraw` в п.5 — только с другим
телом и opcode из `.abi`.

## 7. Смена владельца

Сообщение `ChangeOwner { newOwner }` — тоже вызывается только текущим
owner'ом, позволяет передать контроль над Vault другому адресу
(например, перейти на мультисиг-кошелёк без миграции средств).

## 8. Панель управления (TonConnect, без терминала)

В папке `panel/` — готовая веб-страница `index.html`, где можно логиниться
через **TonConnect** (как в обычных TON-приложениях: сканируете QR или
подключаете кошелёк в один клик) и жать кнопки "Депозит / Вывод / Отправить
NFT" вместо ручных команд в терминале.

### Важно про TonConnect-манифест

Кошельки требуют, чтобы `tonconnect-manifest.json` был доступен по **https**
и лежал рядом со страницей. Просто открыть `index.html` двойным кликом с
диска — не сработает. Варианты:

1. **Локально для теста**: `npx serve panel` (или `python3 -m http.server`
   из папки `panel/`) — откроется на `http://localhost:PORT`. Часть кошельков
   примет и `localhost`, но для мобильных обычно нужен настоящий https.
2. **Быстро и бесплатно**: залить папку `panel/` на GitHub Pages, Vercel или
   Netlify — получите https-адрес, впишите его в `url` внутри
   `tonconnect-manifest.json`.

### Как пользоваться панелью

1. Откройте страницу, переключите сеть **testnet**, пока тестируете.
2. Разверните "Настройки контракта" и впишите:
   - адрес вашего Vault;
   - opcode `Withdraw` и `SendNft` из `build/Vault/Vault.abi` (см. п.2 выше).
   Значения сохранятся в браузере (localStorage), вводить повторно не нужно.
3. Нажмите **Connect wallet** — откроется список кошельков TonConnect,
   подключаете тот, чей адрес указан как `owner` при деплое (для Withdraw/
   SendNft это обязательно, иначе контракт отклонит команду).
4. Депозит доступен с любого кошелька. Вывод GRAM и отправка NFT — только
   с кошелька-владельца, иначе увидите ошибку в логе внизу панели.

## Если нужен другой тип авторизации

Сейчас реализована проверка **по адресу владельца**. Другие варианты,
которые можно добавить в `vault.tact`:

- **Пароль/секрет**: хранить `ownerHash: Int` (например, sha256 от
  пароля + соли) в контракте и проверять `sha256(msg.secret) == self.ownerHash`.
  Минус: секрет в открытом виде проходит через блокчейн в теле сообщения
  (все входящие сообщения публичны), поэтому это слабее, чем адрес-based
  проверка — подходит только как доп. слой, не как единственная защита.
- **Мультиподпись N из M**: хранить список адресов-подписантов и
  требовать подтверждения от M из N перед выполнением — это отдельный,
  более сложный контракт (по сути мини-версия Gnosis Safe для TON).
